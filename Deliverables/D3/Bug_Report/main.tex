\section{Scope and evidence}
The report covers defects with a concrete failure mode and a corresponding code fix. It focuses on authentication and authorization, realtime workflows, database reliability, request integrity, and production configuration. Duplicate observations are consolidated into one defect; supporting test details are retained as evidence rather than counted as separate bugs.

\section{Resolved defects}
\subsection{Credentialed cross-origin Socket.IO access}
\textbf{Impact.} The Socket.IO server reflected arbitrary browser origins while allowing credentials. A malicious origin could attempt to establish a socket using a victim's authenticated browser session and access ride-chat or notification events available to that victim.
\textbf{Cause.} The CORS configuration used a permissive origin reflector with credentialed access.
\textbf{Fix.} The server now derives an explicit origin allow-list from the canonical application URL. Credentialed realtime access is limited to the configured application origin.
\textbf{Evidence.} Adversarial cross-origin handshake coverage verifies rejection of untrusted origins. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Realtime authentication bypassed inactivity expiry}
\textbf{Impact.} A remembered session inactive beyond the seven-day policy could be rejected by HTTP routes but still authenticate a Socket.IO connection.
\textbf{Cause.} Realtime session lookup checked absolute expiry but omitted the inactivity predicate applied by HTTP authentication.
\textbf{Fix.} Realtime authentication and revalidation now enforce the same seven-day inactivity bound as HTTP session validation.
\textbf{Evidence.} Regression coverage compares HTTP and Socket.IO behavior for an old inactive session. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{PostgreSQL TLS certificate verification was disabled}
\textbf{Impact.} External PostgreSQL connections were encrypted but did not verify the server certificate, allowing an intercepted connection to use an untrusted certificate.
\textbf{Cause.} Render-style connection configuration set \texttt{rejectUnauthorized: false}.
\textbf{Fix.} Certificate verification is enabled consistently in the application pool, custom server, migration script, and administrative role script.
\textbf{Evidence.} TLS configuration tests assert certificate verification. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Migration referenced \texttt{rides.locked\_at} before adding it}
\textbf{Impact.} Upgrading an older database could fail while creating a partial index that referenced \texttt{locked\_at}, blocking startup.
\textbf{Cause.} The index was declared before the compatibility \texttt{ALTER TABLE} statement.
\textbf{Fix.} The compatibility column addition now runs before every index or predicate that references the column; the duplicate later alteration was removed.
\textbf{Evidence.} Legacy-schema migration coverage exercises a table without the column. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Client-controlled forwarding headers bypassed IP rate limits}
\textbf{Impact.} Varying a trusted-looking forwarding-header value could create a new rate-limit key for repeated requests, weakening throttling on authentication, registration, chatbot, and ride mutation endpoints.
\textbf{Cause.} IP extraction trusted the first client-supplied \texttt{X-Forwarded-For} value and a separate \texttt{X-Real-IP} path.
\textbf{Fix.} The separate client-controllable \texttt{X-Real-IP} trust path was removed. Extraction uses the final proxy-appended \texttt{X-Forwarded-For} hop and bounds the key value. The overlapping header observations are counted once.
\textbf{Evidence.} Unit tests cover final-hop selection and header handling. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Malformed cookies could throw during websocket authentication}
\textbf{Impact.} A malformed percent-encoded cookie could throw during websocket authentication instead of following the normal unauthenticated rejection path.
\textbf{Cause.} Cookie decoding did not handle malformed percent-encoding.
\textbf{Fix.} Decoding is wrapped in a narrow error handler. The malformed cookie is treated as empty and authentication fails closed without an uncaught parser exception.
\textbf{Evidence.} The websocket regression test supplies malformed percent-encoded cookie input. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.

\subsection{Existing request tables could lack \texttt{updated\_at}}
\textbf{Impact.} An older \texttt{ride\_join\_requests} table without \texttt{updated\_at} could fail when the schema bootstrap referenced the missing column.
\textbf{Cause.} The compatibility migration did not add \texttt{updated\_at} before subsequent backfill statements used it.
\textbf{Fix.} The schema adds the column when absent, backfills it from available timestamps, and applies its default and not-null constraint before later references.
\textbf{Evidence.} Legacy-schema migration coverage exercises the compatibility path. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Password-reset operations were not atomic}
\textbf{Impact.} A failure after token consumption but before updating the password or revoking sessions could leave a reset partially completed.
\textbf{Cause.} Token consumption, password update, and session deletion were separate database operations.
\textbf{Fix.} These operations now run in one transaction and commit or roll back together. Password hashing runs before acquiring the database connection, limiting transaction and row-lock duration.
\textbf{Evidence.} Reset-flow tests cover transactional success and rollback behavior. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Active realtime use did not refresh session activity}
\textbf{Impact.} A user actively using realtime features could have a session expire under the inactivity policy.
\textbf{Cause.} Successful realtime authentication checked the session but did not refresh its activity timestamp.
\textbf{Fix.} Authenticated realtime activity conditionally updates \texttt{last\_activity\_at}, with a five-minute write throttle.
\textbf{Evidence.} Realtime session tests verify activity refresh and throttled writes. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Realtime sockets bypassed account eligibility gates}
\textbf{Impact.} Users with incomplete profiles or unacknowledged warnings could be blocked from protected HTTP workflows but still authenticate realtime access.
\textbf{Cause.} Socket authentication omitted profile-completion and warning-acknowledgement checks.
\textbf{Fix.} Realtime authentication and revalidation now enforce the same eligibility gates as HTTP requests, with the same admin exception.
\textbf{Evidence.} Realtime authorization tests cover incomplete profiles and unacknowledged warnings. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Missing production \texttt{APP\_URL} was not rejected at startup}
\textbf{Impact.} Production could start with an empty Socket.IO origin allow-list, silently preventing browser realtime connections.
\textbf{Cause.} The server fell back to an empty origin when \texttt{APP\_URL} was not configured outside development.
\textbf{Fix.} The server now fails fast in production when \texttt{APP\_URL} is absent or blank.
\textbf{Evidence.} Startup configuration checks cover the missing production URL case. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Production realtime accepted the development cookie name}
\textbf{Impact.} Production Socket.IO authentication accepted the development session-cookie name as an alternative to the host-prefixed production cookie.
\textbf{Cause.} Realtime authentication accepted either cookie name regardless of environment.
\textbf{Fix.} The cookie name is selected by environment: development uses \texttt{crp\_session}; production accepts only \texttt{\_\_Host-crp\_session}.
\textbf{Evidence.} Cookie-policy tests verify environment-specific behavior. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{HTTP authentication could revive an inactivity-expired session}
\textbf{Impact.} An idle-expired remembered session could be rejected during lookup and then refreshed by the same request, allowing later authentication with the stale cookie.
\textbf{Cause.} The refresh update omitted the expiry and seven-day inactivity predicates used by active-session lookup.
\textbf{Fix.} Refresh now requires both absolute expiry and recent activity, so only an already-valid session can be updated.
\textbf{Evidence.} Authentication tests exercise stale sessions across repeated requests. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Existing cursor indexes were not upgraded by \texttt{IF NOT EXISTS}}
\textbf{Impact.} Existing databases retained older same-named indexes, so cursor ordering continued to use outdated index definitions.
\textbf{Cause.} PostgreSQL skips creation when an index of the same name exists; it does not replace its definition.
\textbf{Fix.} The affected notification and complaint-analysis cursor indexes are explicitly dropped and recreated with the required ordering columns.
\textbf{Evidence.} Schema bootstrap and cursor-query coverage exercise the corrected definitions. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/91}{\#91}; Jira \href{https://cs455project.atlassian.net/browse/CS455-121}{CS455-121}.
\subsection{Untyped timestamp parameters caused PostgreSQL 500 responses}
\textbf{Impact.} Seat-request submission and the payment-reminder scheduler could fail against PostgreSQL with a parameter type/operator error and return HTTP 500.
\textbf{Cause.} JavaScript \texttt{Date} parameters were used in timestamp/interval expressions without an explicit PostgreSQL timestamp type.
\textbf{Fix.} The affected SQL parameters now use explicit \texttt{timestamptz} casts.
\textbf{Evidence.} Four focused regression tests are in \file{apps/web/test/integration/bugs/timestamp-parameters.int.test.ts}. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/84}{\#84}; Jira \href{https://cs455project.atlassian.net/browse/CS455-133}{CS455-133}.
\subsection{Idempotency-key reuse replayed a different request}
\textbf{Impact.} Reusing a key for another ride or pickup point returned the original request as though it were a valid retry. A rider could be told a request already existed even though nothing was created for the intended ride, or a changed pickup point could be ignored.
\textbf{Cause.} The idempotency check treated the key alone as sufficient to identify a replay and did not require the ride and pickup payload to match.
\textbf{Fix.} A key now replays only the same logical request. Reuse with different ride or pickup details returns HTTP 409 with \texttt{idempotency\_key\_reused}; the client discards the stale key.
\textbf{Evidence.} Five regression cases are in \file{apps/web/test/integration/bugs/idempotency-key-reuse.int.test.ts}. PR \href{https://github.com/CS455-Carpooling/Campus_Ridepooling_Automation/pull/87}{\#87}; Jira \href{https://cs455project.atlassian.net/browse/CS455-134}{CS455-134}.
